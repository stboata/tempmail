# 临时邮箱

自己部署的临时收件箱，供本人和持有密钥的程序、Agent 使用。任意前缀都能收信，不需要先建邮箱。收到后优先显示验证码，也能查看原文、验证链接及正文图片；不提供发信和普通附件下载。

邮件保留 **24 小时**。查看不会删信，外部验证成功后可以删除指定邮件；遗留邮件自动清理。网页默认查看全部邮件，每分钟刷新一次，也能只看随机生成的地址。

查询框默认“查邮箱”：输入前缀或完整地址，精确查询该邮箱，不搜索正文。切换“搜邮件”才按关键词搜索；已选定邮箱时只搜索该邮箱，否则搜索全部邮件。输入后按回车或点击箭头查询，不逐字发送请求；“查看全部”返回所有邮箱。

## 准备什么

- GitHub 账号，用来保存自己的代码副本。
- Cloudflare 免费账号。
- 一个能接入自己 Cloudflare 账号、能启用邮件路由的域名。域名是否免费取决于域名提供方，本项目不提供域名。
- 一个随机访问密钥，供网页和程序共用。可用密码管理器生成，或运行 `openssl rand -hex 32` 生成 64 位密钥，并自行保存。

运行只用 **一个 Worker（运行网页、接口和收件程序）+ 一个 D1（保存邮件的数据库）**。正文内嵌图片也保存在同一个数据库里。不需要单独创建 Pages、KV、R2，也不需要管理员邮箱。

## 部署

采用 Cloudflare 官方的 [Deploy to Cloudflare](https://developers.cloudflare.com/workers/platform/deploy-buttons/) 流程，避免为本项目维护另一套建库工具。

1. 把域名加入自己的 Cloudflare 账号，按提示修改域名服务商处的名称服务器，直到域名状态为 Active。
2. 打开 [Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/stboata/tempmail)，按提示把代码复制到自己的 GitHub，并创建运行项目及数据库。也可以先 fork 本仓库，再在 Cloudflare 的 Workers 中导入自己的副本。

3. 在部署页填写以下两项，其他资源保持自动创建。接受项目的部署命令 **`npm run deploy`**，不要改成仅运行 `wrangler deploy`，否则会跳过建表。

   | 名称 | 填什么 |
   | --- | --- |
   | `MAIL_DOMAIN` | 收件域名，例如 `stboat.cc.cd`，不要加 `https://`、路径或邮箱前缀；国际化域名填 `xn--` 编码形式 |
   | `ACCESS_KEY` | 32～512 位、不含空格的随机密钥，保存为 Secret（保密配置） |

4. 在 Cloudflare 的 **Email Routing（邮件路由）** 中启用这个域名，按提示添加邮件所需的 DNS 记录。当前界面入口为 **Compute → Email Service → Email Routing**；部分账号仍显示域名下的 **Email → Email Routing**。
5. 在 **Routing Rules → Catch-all rule（接收任意前缀）** 中，选择 **Send to a Worker**，目标选刚部署的项目并启用。收件应交给这个程序，不是转发到个人邮箱。如果平台引导要求验证一个已有邮箱，按平台提示验证；它不是本系统的登录账号。
6. 打开 Worker 项目给出的 `https://项目名.账号子域.workers.dev`，输入密钥使用。需要自己的网址时，在该项目 **Settings → Domains & Routes → Add → Custom Domain** 中添加，例如 `inbox.stboat.cc.cd`。

网站网址和收件域名用途不同。例如网站是 `https://inbox.stboat.cc.cd`，邮箱是 `任意前缀@stboat.cc.cd`。网页和接口使用同一个网站网址，无需填写连接地址。域名已有其他邮箱服务时，应先处理已有的 MX 记录和收件规则，避免相互冲突。

部署命令先应用数据库更新，再发布程序；重复部署不会重建或清空邮件。密钥不写进静态网页、仓库或示例文件。更改密钥后，人和程序都要改用新密钥。

## 部署后验收

1. 从另一个正常邮箱向 `自己随便编的前缀@收件域名` 发送测试邮件。
2. 打开网页登录，确认全部邮件中出现该邮件；搜索前缀，查看原文并删除。
3. 按 [API.md](API.md) 让程序查询另一个地址，检查时间筛选、读取和删除。
4. 在 Cloudflare 确认定时任务已部署，观察后续到期邮件被清理。

首页检查两个 Cloudflare 公共地址，任一可达就显示登录框；无论成功或失败，先完整播放约 1.6 秒的 mail 手写动画，再短暂停留，约 1.8 秒后切换。这个检查不依赖你已部署邮箱，只说明当前网络能连接到 Cloudflare，不能证明本实例的数据库或收件规则正常。点击登录后才验证密钥和邮箱服务；仍须做一次真实投递。网页本身无法下载时，由浏览器提示访问失败。

## 免费资源与保存上限

按个人临时收信场景使用免费套餐，不启用付费产品。免费额度仍受 Cloudflare 同账号的其他项目使用量影响。

| 项目 | 当前行为 |
| --- | --- |
| 有效期 | 接收后 24 小时立即不可查询、阅读或取图；每 30 分钟从数据库清理到期内容 |
| 总量 | 最多 5,000 封、约 100 MiB 内容估算量；实际数据库还包含索引等开销 |
| 原始邮件 | 超过 2 MiB 只留基本记录，标记“正文未保存” |
| 正文 | 文本与 HTML 合计超过 512 KiB，只留基本记录 |
| 内嵌图片 | 只保存正文引用的 PNG/JPEG/GIF/WebP；单张最多 256 KiB，每封最多 8 张、合计 512 KiB；超限部分标记未保存 |
| 验证码 | 提取紧邻验证提示的 4～8 位常见数字或字母数字码；链接编号不作为码，存在冲突或未识别时返回空字符串，仍可查看邮件 |
| 错误密钥 | 按来源 IP 约 5 次/分钟限制失败尝试；不加载额外验证脚本 |
| 容量或写入失败 | 不假装已保存；容量不足先清理到期邮件再重试一次，仍失败则交给平台的失败处理 |

外部图片默认不加载，可在阅读时主动显示；它们由发件方提供，删除本地邮件不会删除外部服务器上的图片。普通附件不保存。图片可以查看，不代表能自动识别图中验证码。

失败尝试限流由 Cloudflare 就近节点近似计数，不是全网统一的精确限额，应配合随机长密钥使用。

[Workers 免费额度](https://developers.cloudflare.com/workers/platform/limits/)目前为每日 10 万请求、每次 10 ms CPU；[D1](https://developers.cloudflare.com/d1/platform/pricing/)为每日 500 万行读取、10 万行写入，免费单库最大 500 MB。图片和索引也会消耗额度，关键词查询可能扫描多行。2 MiB 是本程序的处理上限，不保证复杂邮件在免费 CPU 限制内都能处理；线上需查看实际用量和收件失败日志。

## 本地运行与检查

需要 Node.js 22.12 或更新版本。

```sh
npm ci
cp .dev.vars.example .dev.vars
```

在 `.dev.vars` 填入自己的本地测试密钥，再运行：

```sh
npm run dev
```

默认打开 `http://localhost:8787`。本地默认收件域名是 `example.com`；本地运行不接收互联网邮件，真实收件需要完成前面的域名部署。

`npm run check` 检查真实部署包和绑定配置，不发布远程资源。本地测试代码及模拟邮件保留在已忽略的 `test/` 中；该目录、`.dev.vars`、本地数据库和构建产物均不提交到 GitHub。

GitHub 上的提交和拉取请求只运行安装与部署打包检查，不需要本地测试文件或 Cloudflare 密钥，也不发布网站。直接打开 HTML 可以显示登录页，读取邮件需要同源后端；没有演示数据或绕过密钥的入口。新部署只创建数据表，不写入示例邮件。

## 代码入口

- `inbox.html`：现有单文件网页，构建时复制为网站首页。
- `src/worker.js`：接口、密钥校验、图片读取和平台入口。
- `src/mail.js`：收件、正文解析、提码及清理。
- `migrations/`：数据库建表和后续升级；不要修改已经在线应用过的迁移，应新增文件。
- `wrangler.json`：部署、数据库连接、失败尝试限流和定时任务配置。

收件与部署思路参考 [maillab/cloud-mail](https://github.com/maillab/cloud-mail)，核查版本为 `a792cdcd5c3291ac718b97489b1be19367121969`。本项目按临时收件场景编写精简后端，没有带入原项目的账号、角色、发件或管理后台。运行依赖只有 PostalMime（解析邮件）和 entities（还原 HTML 字符），许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
